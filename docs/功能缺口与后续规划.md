# Botly 功能缺口与后续规划

> 对照文档：《多智能体工作台 需求文档 v0.3》
> 对照代码：2026-10-30 当前实现（Postgres + Next.js）
> 用途：列出尚未实现、只有替代实现、以及运维/非功能缺口，供排期和验收使用。

状态说明：

- **未实现**：文档有明确要求，代码里没有对应能力。
- **替代实现**：功能目标基本达到，但交互或数据结构与文档原文不同。
- **偏差**：行为与文档不一致，需要决定改代码还是改文档。
- **运维缺口**：不影响本地功能，但上线前必须补。

## 3. P0 中仍有替代实现或偏差的部分

这些需求文档标为 P0，但当前实现与原文不完全一致。需要逐项决定「改代码」还是「改文档」。

### 3.1 任务卡 / 完成卡 / 交接提示

- **文档要求**：CHT-05、RUN-08、7.1 要求任务卡片挂在派活消息下方，子任务完成后生成完成卡片，
  总指挥交接时出现灰色交接提示；消息类型包含 `task`、`task_done`、`handoff`。
- **当前实现**：没有发出这三种消息类型。总指挥用一条 `@成员 指令` 的普通消息派活；
  子 Agent 的文本实时镜像到主线程，最终回复升级为带「已完成 · 耗时 · token」脚注的气泡；
  工具调用/返回逐条同步到群聊并默认展开（含失败/超时/未授权的返回）；完整过程仍在子线程。
- **影响**：群聊阅读体验更自然，但任何依赖 `task` / `task_done` / `handoff` 类型的消费者
  （导出、第三方接入、历史渲染）拿不到这些类型。
- **建议**：保留当前交互，同时补发 `task` / `task_done` 兼容消息（不额外渲染），或明确修改文档。
- **补充（2026-10）**：子 agent 的任务详情已直接进入群聊——派活消息与子 Bot 回复下方各有一行概要
  （状态、第几次执行、已运行时长、token），并可点「查看详情」原地展开指令、期望产出、工具调用
  次数等；右侧任务面板保留为备用入口。token 用量现在每次模型调用后都会通过 `task.status`
  事件实时推送，不必等执行结束。

### 3.2 7.1 左侧栏的 Bot 列表

- **文档要求**：桌面端左栏包含「群聊与 Bot 列表」。
- **当前实现**：左栏只有群聊；Bot 在左侧导航的「Bot」页管理。
- **影响**：不阻塞核心流程，属于布局差异。

### 3.3 MOD-02 保存模型接入时的校验

- **文档要求**：保存时校验 ① 连通性 ② 支持流式输出 ③ 支持工具调用；不支持工具调用的模型不能被选作总指挥。
- **已实现（2026-10）**：保存厂商时真实探测首个模型的三项能力（流式 + 工具调用），结果按模型
  持久化在 `providers.models`；「测试」检测首个模型，「检测能力」批量检测（单次最多 12 个、
  并发 4）。Bot 选模型时按结果提示，明确不可用的置灰；群聊创建 / 更换总指挥时后端拒绝明确
  不支持工具调用或流式输出的模型，自动挑选总指挥会跳过这类 Bot。
- **残留**：保存本身不阻断（探测失败只把厂商状态标红），因为自建网关的探测限制各不相同；
  能力是三态，**没探测过的模型不拦截**——这类模型仍可能到第一次执行才失败。
- **建议**：引导页/注册流程里提示用户先点一次「检测能力」；这条已在第 7 节列为产品待确认项。

### 3.4 APV-03 审批过期的语义

- **文档要求**：审批 24 小时过期，过期视为拒绝（原因「用户未在规定时间内处理」），并把原因回传给 Bot。
- **当前实现**：过期后把执行置为「失败」并通知用户，不会把过期原因作为工具结果交回总指挥。
- **影响**：总指挥无法在过期后改派或跳过；文档 6.1 允许等待 → 失败，因此不算完全未实现。
- **建议**：如需严格对齐，把过期改成「重新入队 + 审批结果=拒绝」，由总指挥决定后续。

### 3.5 TOL-01 未配置搜索 Key 时的工具可用性

- **文档要求**：未配置搜索服务 Key 时 `web_search` 不可选。
- **当前实现**：仍可选；未配置 Key 时回退到 DuckDuckGo HTML 公共搜索。
- **影响**：结果不稳定，且用户可能不知道查询发给了第三方。
- **建议**：在 Bot 工具选择处根据 `search_configured` 禁用，或保留回退但在界面明确提示。

### 3.6 RUN-10 同一子任务最多改派 1 次

- **文档要求**：同一子任务失败后最多改派 1 次。
- **已修复（2026-10）**：子任务有了稳定标识 `tasks.step_key`——`delegate` 新增 `step`
  参数（计划步骤的标题或序号，改派时保持不变），计数按它而不是指令原文；没传 `step`
  时退回指令文本，兼容旧行为。改派换个说法、换个人都不再绕过上限。
- **残留**：`step` 是否原样回传取决于模型，系统提示里已明确要求；没传时仍按文本匹配。

### 3.7 CHT-04 成员栏的「正在输入」

- **文档要求**：Bot 处理中在成员栏和消息流显示「正在输入」。
- **当前实现**：消息流在模型未输出时显示三点跳动，输出后显示气泡；成员栏显示「工作中/等待处理」。
- **影响**：语义等价，文案与位置不同。

### 3.8 8.3 可靠性与幂等

- **已实现**：stale lease 回收、从检查点恢复、工具调用按 call id 去重、停止/超限收尾。
- **已修复（2026-10）**：模型节点重放。每轮模型输出落库时，在同一个事务里记下
  `runs.last_turn_message_id` 并计一步；图重放 model 节点时，如果线程最后一条消息就是这个
  标记，直接复用上一轮结果（工具轮交给 tool 节点按 call id 继续），不再调一次模型、
  不重复计步/计费、不产生重复消息。崩溃残留的流式草稿会在下一轮开始时清掉。
- **残留**：
  - Postgres 下 `events` 自增 id 在插入时分配、提交时可见；并发事务可能让较小 id 晚出现，
    单条 SSE 事件可能被跳过（前端重连/快照刷新可兜底）。彻底修复需按群聊分配序号。
  - 「模型轮已提交、工具轮也执行完、检查点却还停在 model 节点」这种连续两步都没写入检查点
    的极端情况，仍会重跑一次模型：消息不会重复，但多花一次调用。

### 3.9 8.4 SSRF 的 DNS 重绑定

- **已实现**：禁止内网/回环/链路本地/元数据地址，限制 5 次重定向、5 MB 响应体。
- **已修复（2026-10-30）**：域名解析后不再一刀切拦截 reserved 段——本地代理（Clash/Surge）
  的 fake-ip 段 `198.18.0.0/15` 会被 Python 判为 `is_private`，导致所有公网域名被误杀成内网。
  现在域名解析到 fake-ip 段放行（IP 字面量输入该段仍拒绝），其它私网/回环/链路本地照常拦截。
- **残留**：校验时 `getaddrinfo` 与 httpx 实际连接之间仍可能发生 DNS 重绑定（TOCTOU）。
- **建议**：改用固定解析结果连接（resolve + IP 连接 + Host 头）或可信 DNS 代理。

### 3.10 LIM-01 步数与运行时长

- **文档要求**：单次执行最大步数 40（可调）、最长运行时长 30 分钟（可调）。
- **当前实现**：按产品决定**已删除**两个上限，只保留 token 预算、委派深度、用户停止。
- **已决议（2026-10）**：保持删除，并已同步修订需求文档——LIM-01 / LIM-02、验收标准第 8 条、
  附录 A、术语表与 8.6 告警口径均已改为「token 预算兜底 + 可观测的卡死指标」，
  不再把步数/时长当作执行上限。

## 5. 已经完成的 P1（避免误列）

- BOT-05 Bot 模板（6 个内置角色）
- APV-06 「本群聊始终允许此工具」（L3 不提供）
- RUN-13 执行中插话
- MOD-05 模型 token 单价（现在会按厂商参考价自动预置，可手动改）
- MOD-06 429/超时重试与用量页错误率
- LIM-05 按 Bot / 模型 / 群聊 / 日期统计用量与费用
- FIL-03 用户上传文件到沙箱
- **ACC-07 删除账号**（2026-10-30）：删除后立即停用并终止运行中的执行，数据保留 30 天；
  `scripts/purge_accounts.py` 支持列出 / 恢复 / 立即清除，到期后 Worker 小时级任务自动彻底清除
  （业务表、沙箱文件、上传图片、登录记录与加密 Key）。停用期间所有接口返回 401，无法登录。
- **15.2 导出群聊记录**（2026-10-30）：`GET /api/chats/{id}/export` 输出 Markdown 附件，
  按日期分组，包含用户消息、Bot 最终回复、计划卡片与系统提示；工具调用、派活副本与子 Bot
  过程镜像不重复导出。聊天页菜单可直接下载。
- **MEM-05 长对话自动摘要与截断**（2026-10-30）：主线程历史超过 token 阈值（默认 8k、
  可配 `BOTLY_SUMMARY_THRESHOLD_TOKENS` / `BOTLY_SUMMARY_MAX_ITEMS`）时，用总指挥模型把
  「最近 40 条之前」的旧消息压缩成摘要，持久化到 `threads.summary` + `summary_upto_seq`
  并注入后续上下文，保留最近 40 条原文；摘要失败退回硬截断。
- **MEM-04 记忆候选**（2026-10-30）：执行成功后后台用总指挥模型从「用户原话 + 执行汇总」提取
  最多 3 条值得长期记住的信息，写入 `memory_candidates`（不采信网页/工具返回，避免污染）；
  记忆页显示「待确认」，用户保存才写入 `memories`，忽略则丢弃；候选生成失败不影响执行。

## 7. 需要产品确认的口径

1. ~~**步数 / 运行时长上限**~~：已确认保持删除，需求文档已同步修订（见 3.10）。
2. **任务卡 / 完成卡 / 交接提示**：保留当前群聊气泡 + 脚注，还是补文档要求的独立卡片消息类型？
3. **MOD-02 的强度**：已实现「保存不阻断、选总指挥时拦截」。是否再进一步，在保存时硬阻断不支持流式/工具调用的模型？（会增加保存耗时，可能挡住自建网关）
4. **搜索服务商**：继续用 Tavily + DuckDuckGo 回退，还是接入指定服务商并强制配置 Key？
5. **引导页推荐模型**：是否在注册/首次配置时推荐 2–3 个支持工具调用的模型？
