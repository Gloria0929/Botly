## 3. P0 中仍有替代实现或偏差的部分

这些需求文档标为 P0，但当前实现与原文不完全一致。需要逐项决定「改代码」还是「改文档」。

### 3.1 任务卡 / 完成卡 / 交接提示

- **文档要求**：CHT-05、RUN-08、7.1 要求任务卡片挂在派任务消息下方，子任务完成后生成完成卡片，
  总指挥交接时出现灰色交接提示；消息类型包含 `task`、`task_done`、`handoff`。
- **原实现（2026-11-02 前）**：没有发出这三种消息类型。总指挥用一条 `@成员 指令` 的普通消息派任务；
  子 Agent 的文本实时镜像到主线程，最终回复升级为带「已完成 · 耗时 · token」脚注的气泡；
  工具调用/返回只落在子线程（群聊仅展示 bot 的聊天记录，过程进任务面板查看，
  含失败/超时/未授权的返回）。
- **影响**：群聊阅读体验更自然，但任何依赖 `task` / `task_done` / `handoff` 类型的消费者
  （导出、第三方接入、历史渲染）拿不到这些类型。
- **建议**：保留当前交互，同时补发 `task` / `task_done` 兼容消息（不额外渲染），或明确修改文档。
- **已补齐（2026-11-02）**：后端开始真实落库这三类消息——派任务时写 `task`（串行与并行两条路径都有），
  子任务完成 / 失败时写 `task_done`，结果交回总指挥时写 `handoff`；每条都带 `meta.compat=True`
  与 `meta.task_id`，按 (run_id, task_id, 类型) 去重，图节点重放不会写第二条。群聊交互保持不变：
  前端在消息流里按 `compat` 过滤，不额外渲染（仍是「@成员 指令」+ 概要行 + 子 Bot 气泡）；
  导出（15.2）改为消费这些类型，任务、完成（含执行者 / 耗时 / token）与交接提示都会出现在 Markdown 里。
  `tests/test_p0_gaps.py::test_compat_task_task_done_handoff_messages` 覆盖落库、去重键与导出。
- **补充（2026-10）**：子 agent 的任务详情已直接进入群聊——派任务消息与子 Bot 回复下方各有一行概要
  （状态、第几次执行、已运行时长、token），并可点「查看详情」原地展开指令、期望产出；
  完整执行过程（含工具调用）在右侧任务面板查看。总指挥自己发起的工具调用（搜索、读网页、读写文件）
  在主线程，面板顶部单列一条「总指挥 · 工具调用与返回」入口；派任务 / 计划 / 提问不重复列出，
  它们在群聊里各有卡片。token 用量现在每次模型调用后都会通过 `task.status`
  事件实时推送，不必等执行结束。

### 3.3 MOD-02 保存模型接入时的校验

- **文档要求**：保存时校验 ① 连通性 ② 支持流式输出 ③ 支持工具调用；不支持工具调用的模型不能被选作总指挥。
- **已实现（2026-10）**：保存厂商时真实探测首个模型的三项能力（流式 + 工具调用），结果按模型
  持久化在 `providers.models`；「测试」检测首个模型，「检测能力」批量检测（单次最多 12 个、
  并发 4）。Bot 选模型时按结果提示，明确不可用的置灰；群聊创建 / 更换总指挥时后端拒绝明确
  不支持工具调用或流式输出的模型，自动挑选总指挥会跳过这类 Bot。
- **补充（2026-11-02）**：「检测能力」完成后会弹出逐模型结果（流式 / 工具调用 / 失败原因），
  厂商卡片显示「上次检测 …」；价格弹窗里每个模型也标出能力，未检测的标「未知」。
- **已补齐（2026-11-02）**：保存改为**硬校验**——连通性失败或明确不支持流式输出时拒绝保存
  （400，错误里带模型名与探测信息）；工具调用不阻断保存（不支持工具调用的模型仍可作普通 Bot，
  由 Bot 选模型处提示、选总指挥处拦截），三态里的「无法判断」不拦截，避免误杀自建网关。
  改 `base_url` / API Key 的 PATCH 也会重新探测并同样校验，不能靠编辑绕过创建时的检查。
  `capabilities.hard_save_block_reason` 收口口径，`tests/test_model_capability.py` 覆盖
  「不支持流式被拒」「连不上被拒」「不支持工具调用可保存」「改 Key 重新校验且失败不落库」。
- **残留**：没探测过的模型仍不拦截（只在选总指挥时按「明确不支持」拦截），
  引导用户先点一次「检测能力」仍在第 7 节列为产品待确认项。
- **建议**：引导页/注册流程里提示用户先点一次「检测能力」；这条已在第 7 节列为产品待确认项。

### 3.4 APV-03 审批过期的语义

- **文档要求**：审批 24 小时过期，过期视为拒绝（原因「用户未在规定时间内处理」），并把原因回传给 Bot。
- **已修复（2026-11-02）**：过期不再把执行判失败。`maintenance.expire_approval` 把审批置 `expired`，
  若执行确实停在这张审批上（`resume_payload.approval_id` 匹配），就写一条系统消息
  「审批已过期（工具未执行）…已交回总指挥」，把执行重新置为 `queued`；图重放工具节点时
  `_approval_gate` 看到 `expired` 会把「审批已过期，未执行」作为工具结果交给模型，
  总指挥可改派/跳过/结束。审批与执行状态不匹配时只标记过期，不误唤醒。
- **残留**：过期后总指挥能看到的只有「工具未执行」，没有单独的结构化「拒绝」字段；
  与用户主动拒绝在语义上等价，但审计时只能靠审批状态区分。
- **测试**：`server/tests/test_p0_gaps.py` 覆盖「过期→重新入队 + 系统消息 + 通知」与「不误唤醒」。

### 3.5 TOL-01 未配置搜索 Key 时的工具可用性

- **口径（2026-11-02 调整）**：未配置搜索服务 Key 时 `web_search` 不再禁用，而是自动回退
  DuckDuckGo 免密钥搜索（Tavily 为主路径，失败/无结果时同样回退）。
- **已实现**：`GET /api/bots/tools` 对 `web_search` 恒返回 `available=true`，无 Key 时带
  `reason` 提示「将使用 DuckDuckGo 免密钥搜索」，Bot 编辑页以弱提示展示；设置页「网页搜索」
  区显示已配置/未配置，并说明回退行为。
- **实现细节**：`_web_search` 拆成 `_tavily_search` + `_ddg_search`；DDG 依次尝试 html 端点
  POST → html 端点 GET → lite 端点 POST，解析结果时把 `duckduckgo.com/l/?uddg=` 跳转链接
  还原成真实网址（否则 `web_read` 会去读跳转页），并对结果去重。工具结果末尾注明本次来源。
- **测试**：`server/tests/test_p0_gaps.py` 覆盖「无 Key 仍可选 + 提示文案」「配置/清空 Key
  后状态切换」与「DDG 结果链接还原 + 去重」。
- **残留**：DuckDuckGo 反爬时会返回 202/空页，此时只能报「搜索失败」并建议配置 Key；免密钥
  搜索没有摘要，只有标题与链接。

### 3.6 RUN-10 同一子任务最多改派 1 次

- **文档要求**：同一子任务失败后最多改派 1 次。
- **已修复（2026-10）**：子任务有了稳定标识 `tasks.step_key`——`delegate` 新增 `step`
  参数（计划步骤的标题或序号，改派时保持不变），计数按它而不是指令原文；没传 `step`

- **残留**：`step` 是否原样回传取决于模型，系统提示里已明确要求；没传时仍按文本匹配。

### 3.7 CHT-04 成员栏的「正在输入」

- **文档要求**：Bot 处理中在成员栏和消息流显示「正在输入」。
- **原实现（2026-11-02 前）**：消息流在模型未输出时显示三点跳动，输出后显示气泡；成员栏显示「工作中/等待处理」。
- **影响**：语义等价，文案与位置不同。
- **已补齐（2026-11-02）**：成员栏在任一成员 `status=working` 时显示三点跳动 + 「正在输入…」，
  头像悬停提示也改为「正在输入…」；消息流在模型还没吐字时（`streaming` 且无内容）显示

### 3.8 8.3 可靠性与幂等

- **已实现**：stale lease 回收、从检查点恢复、工具调用按 call id 去重、停止/超限收尾。
- **已修复（2026-10）**：模型节点重放。每轮模型输出落库时，在同一个事务里记下
  `runs.last_turn_message_id` 并计一步；图重放 model 节点时，如果线程最后一条消息就是这个
  标记，直接复用上一轮结果（工具轮交给 tool 节点按 call id 继续），不再调一次模型、
  不重复计步/计费、不产生重复消息。崩溃残留的流式草稿会在下一轮开始时清掉。
- **残留**：
  - Postgres 下 `events` 自增 id 在插入时分配、提交时可见；并发事务可能让较小 id 晚出现，
    单条 SSE 事件可能被跳过（前端重连/快照刷新可兜底）。彻底修复需按群聊分配序号。
  - 「模型轮已提交、工具轮也执行完、检查点却还停在 model 节点」这种连续两步都没写入检查点
    的极端情况，仍会重跑一次模型：消息不会重复，但多花一次调用。
- **思维链回传的漏网场景（2026-10-30 修复）**：崩溃/重启/插话中止时残留的流式草稿会被标成
  `interrupted`，此前仍会作为 assistant 消息进入下一次请求，缺 `reasoning_content` 且内容是被截断的
  半句，思考模式模型直接返回 400（`must be passed back`）。现在构造上下文时 `streaming` 与
  `interrupted` 一律跳过，且所有 assistant 消息都显式带 `reasoning_content`（无思考内容填空串）。
  实测：缺字段 → 400，空串 → 200。

### 3.9 8.4 SSRF 的 DNS 重绑定

- **已实现**：禁止内网/回环/链路本地/元数据地址，限制 5 次重定向、5 MB 响应体。
- **已修复（2026-10-30）**：域名解析后不再一刀切拦截 reserved 段——本地代理（Clash/Surge）
  的 fake-ip 段 `198.18.0.0/15` 会被 Python 判为 `is_private`，导致所有公网域名被误杀成内网。
  现在域名解析到 fake-ip 段放行（IP 字面量输入该段仍拒绝），其它私网/回环/链路本地照常拦截。
- **残留**：校验时 `getaddrinfo` 与 httpx 实际连接之间仍可能发生 DNS 重绑定（TOCTOU）。
- **建议**：改用固定解析结果连接（resolve + IP 连接 + Host 头）或可信 DNS 代理。

### 3.11 web_read 的读取质量

- **已修复（2026-10-30）**：跟随重定向时误用了 yarl 的 `URL.human_repr()`（httpx.URL 没有这个方法），
  任何 3xx 跳转都会直接报 `'URL' object has no attribute 'human_repr'`；改为 `str(httpx.URL(...).join(...))`。
- **429 退避**：公共站点限速时按 `Retry-After` 等一次（最多 3 秒）再请求，第二次仍 429 才判失败，
  提示「目标站点限制了自动访问」；401/403 单独提示可能需要登录或反爬校验。
- **空壳页面不再算成功**：不少站点（Reddit、知乎等）对非浏览器请求只返回一个脚本外壳，
  解析后只剩站名几个字。现在正文短于 `WEB_READ_MIN_TEXT`（120 字）时直接返回
  「只取到页面框架，没有正文」，避免模型把空内容当真、凭空编造。
- **残留**：这类站点目前没有兜底通道——Reddit 在本机网络下 `www`、`old`、`api`、`.json`
  全部被拦（403/跳转），只能换来源。真要覆盖，需要接一个渲染服务或第三方正文提取 API。

### 3.12 CHT-03 执行中的发送按钮

- **文档要求**：同一群聊同一时间只允许一个进行中的执行；执行进行中时输入框可输入，
  但发送按钮变为「停止」。
- **已补齐（2026-11-02）**：执行中主按钮直接变为红色「停止」，点击停止当前执行
  （已完成步骤与产物保留）；原来「停止」是独立按钮、发送按钮仍是箭头，与文档不一致。
- **插话（RUN-13）不变**：执行中输入文字后按 Enter 仍按插话发送，输入区下方提示改为
  「执行中 Enter 发送 = 插话」，避免两种动作互相遮挡。

- **ACC-09 第三方登录（Google / GitHub）**（2026-11-02）：登录页按后端配置显隐按钮，
  `GET /auth/oauth/providers` 返回启用状态；授权走 `state + HttpOnly nonce` 双校验。
  回调三条分支：已绑定直接登录 / 邮箱已验证且命中现有账号则自动绑定 / 否则按
  `BOTLY_OAUTH_ALLOW_SIGNUP`（默认 1）决定建号（随机密码 + 默认 Bot + 首个群聊）还是提示先用邀请码注册。
  已有账号可在设置页「账号」绑定与**解绑**（`DELETE /auth/oauth/{provider}`，
  解绑最后一个时会提示确认邮箱密码可用）；设置页还会给出当前回调地址并支持复制。
  `tests/test_oauth.py` 14 项覆盖。
  - **残留**：① client id/secret 只能改 `.env`，没有设置页配置入口（部署级密钥不进数据库）；
    ② 注册页没有第三方登录入口（登录页有，首次登录会自动建号）；
    ③ 回调地址按浏览器 Host 现算，换访问地址（127.0.0.1 / 局域网 IP）就要在对方后台多登记一条，
    需要固定时配 `BOTLY_OAUTH_REDIRECT_BASE`。
- **沙箱预装镜像**（2026-11-02）：`deploy/sandbox.Dockerfile`（ubuntu:24.04 + python3 / nodejs /
  git / curl / jq / ripgrep / build-essential 等）+ `scripts/build_sandbox.sh`。
  `BOTLY_LINUX_SANDBOX_IMAGE` 默认指向 `botly-sandbox:24.04`，镜像不存在时自动退回
  `LINUX_SANDBOX_BASELINE_IMAGE`（默认 ubuntu:24.04）并记 warning，不会卡住建群。
  `start.sh` 启动时检测缺失会构建一次（`SKIP_SANDBOX_IMAGE=1` 跳过）。
  效果：新群容器秒起，python/node 不用再等 50–80 秒的首次 apt。
