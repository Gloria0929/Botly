# 直接连接 CubeSandbox

2026-11-03：设置页提供直接连接自己部署的 Cube 后端的表单。Cube 连接、模板和 API Key 按账号隔离；每个群聊复用自己的远端沙箱。Docker 仅供本机测试。

本机 Docker 沙箱仍以 root 运行并允许联网（用于命令执行和安装依赖），但容器会移除 Linux capabilities 并启用 `no-new-privileges`。这属于开发/测试后端，不应作为多租户生产隔离边界；生产环境应使用独立的远端沙箱服务。

## 使用入口

1. 打开「设置 → 沙箱接入」。
2. 填写 Cube 后端地址（如 `http://服务器IP:3000`）和已经制作好的模板 ID。
3. 后端开启鉴权时填写 API Key；保存后不回显明文，留空会保留旧密钥，勾选「移除已保存的 API Key」可清空。
4. 远程访问无法解析 `*.cube.app` 时填写代理节点 IP（例如 `203.0.113.10`）；粘贴 `http://203.0.113.10` 也会自动提取 IP，保留单独填写的端口。代理 HTTP 端口默认 80，沙箱域名默认 `cube.app`。
5. 点击「测试连接」，Botly 会创建一个临时沙箱，验证命令和文件读写并释放。
6. 点击「保存连接」。当前账号的 `run_command` / `code_exec` 自动使用 Cube，其他账号不受影响。

保存后展示连接摘要，含后端地址、模板、代理节点和密钥状态。「已配置，待验证」「验证通过」「验证失败」分别表示配置与最近一次测试结果；修改配置会清除旧验证结果，原样保存则保留。通过「编辑连接」重新展开表单。

「远端运行记录」显示已创建会话沙箱的 ID、最近实际执行时间与退出码，可跳到对应会话；这是持久化记录，不代表所有远端实例当前仍在运行。需在智能体工具设置中启用 `code_exec` 或 `run_command`，并实际调用工具，才会在 Cube 上运行；普通模型回复不会启动沙箱。

聊天右侧提供「任务、产物、终端」三个页签。Cube 终端使用 xterm 渲染真实 PTY，通过同源 WebSocket 转发键盘输入和远端输出，不再由前端拼接 `cube:/workspace`。打开终端时创建或恢复一次 shell，此后命令直接交给同一个进程；`cd`、方向键历史、Ctrl+C、Ctrl+L 和交互程序由远端 shell 处理。初始工作区为 `/workspace`，提示符及路径由真实 shell 输出；顶栏路径通过 shell 的 OSC 7 目录事件更新。

手动 PTY 输入不进入 Worker 队列，也不在每条命令前后扫描或同步文件。首次连接仍需创建/恢复沙箱，之后复用连接；切换侧栏页签时连接保留，断线后按 `cube_sessions.pty_pid` 重连。页面关闭后终端传输闲置 10 分钟会释放，远端 shell 在生命周期内保留，重连可恢复；终端流最长 1 小时，可通过重新连接继续。Agent 仍通过受审批约束的代码/命令工具执行，其执行过程统一在任务详情中查看。Docker 仅用于本机测试，交互终端目前仅支持 Cube PTY。

终端进程退出或沙箱失效时显示中文提示和「重新连接」，并清理失效 PID。重新连接不会复用失效终端；旧 shell 不存在时创建新 shell，沙箱已删除或过期时创建新沙箱。输入失败时不重放键盘内容，避免重复执行命令。

仅终端进程退出时，工作文件仍保存在原沙箱。沙箱已删除而需要新建时，先将 Botly 本地副本中的附件、工作文件和 `output/` 文件按原路径上传，再保存新沙箱 ID，技能从技能库重新安装。文件恢复失败时不替换原会话记录，也不删除本地副本；可以再次重新连接。恢复范围仅限已上传至 Botly 或经 Agent 工具同步回本地的文件；手动终端中新建或修改但尚未同步的内容、系统安装的软件及运行中进程无法通过本地文件恢复。

产物列表仅显示沙箱 `/workspace/output/` 目录中的文件（包含子目录），不要求文件由 Agent 创建。Agent 将交付文件写入该目录，并行任务使用 `output/tasks/<任务ID>/`；执行工作目录保持 `/workspace` 或原来的独立任务目录。技能、依赖、缓存和目录外的用户附件不列入产物区；点击文件在侧栏内预览，不弹出窗口。列表及预览提供删除按钮，确认后同步删除 Cube 工作区文件、本地副本和产物记录；远端删除失败时保留记录并提示错误。安装的技能仍保留在沙箱目录中。手动终端的文件操作直接发生在远端，Agent 工具执行时同步文件，并登记已有及新建的 `output` 文件。

技能库导入、新建、更新和删除会同步当前账号已有的会话沙箱。每个技能的真实目录为 `/workspace/skills/<名称>-<技能ID>`，包含 `SKILL.md`、脚本、数据及参考文件；技能卡片可复制路径。源文件保存在后端 `data/skill_packages/<用户>/<技能>` 作为管理和恢复缓存，脚本在沙箱目录中执行。GitHub 导入递归下载技能目录内的子目录，并保留原始 `SKILL.md`。停用技能保留安装文件，但不再提供给 Bot；删除技能会清理对应的受管理目录。

尚未创建或已经过期的沙箱在下一次执行/打开终端时安装技能；安装失败会提示待重试。文件哈希保存在 `cube_sessions.skills_manifest`，只上传变更内容；技能同步发生在导入、更新和打开沙箱时，PTY 的键盘输入不触发同步。Docker 测试环境写入同一个挂载工作区，技能始终不登记到产物列表。技能脚本所需的依赖由 Agent 按技能说明在沙箱中安装，仍使用命令工具的审批规则。

后端地址从 Botly 的 API / Worker 所在机器访问；如果后端部署在另一台机器，不能填写该机器意义上的 `127.0.0.1`。部署于容器时也应填写容器可访问的 CubeAPI 地址。

## 执行与文件

- 通过官方 `cubesandbox==0.7.3` SDK 的显式 `Config` 连接用户配置的 CubeAPI；不修改进程级环境变量。
- 工具返回注明「运行环境：Cube」、远端沙箱 ID 与退出码，便于核对执行位置。
- 远端 ID 存于 `cube_sessions`，按账号 + 群聊隔离，API、Worker 和重启后通过 `Sandbox.connect` 复用。远端过期/删除时重新创建，并恢复本地工作区文件。
- 首次执行懒创建沙箱，建群不消耗远端资源。实例空闲超时配置为暂停。
- 上传文件和本地文件工具产物在命令前同步到远端 `/workspace`；命令结束后，远端工作文件同步回本地文件区，其中 `output/` 文件登记到产物面板。支持二进制文件，不经过 UTF-8 文本转换。
- 同群聊的远端执行与同步使用跨 Worker 锁；不同群聊可并行。单文件 10 MB、账号文件区 200 MB，单次工作区扫描最多 2000 项；不下载符号链接。
- `code_exec` 支持 python/node/bash/sh，使用模板中对应解释器，从 stdin 接收代码。命令工作目录为 `/workspace`，远端 `timeout` 限制执行时长。
- `run_command` 为 L3，默认需要审批；审批卡片可点击「在本群聊始终允许」，后续该群聊的同一工具不再请求审批，可在群聊设置中撤销。代码执行默认 L2；设为 L3 时同样支持群聊工具白名单。此规则与沙箱提供方无关。

断开连接会释放当前账号的远端实例，保留已经同步回本地的文件；正在执行时需先停止。改变后端或模板前需断开旧连接，API Key 轮换或代理配置修正可沿用原实例。解散群聊和到期清除账号也会清理绑定的远端实例。

## 接口与部署

| 接口 | 用途 |
| --- | --- |
| `GET /api/sandbox` | 当前账号沙箱状态与配置，密钥只返回是否已配置 |
| `PUT /api/sandbox/cube` | 保存后端地址、模板、可选密钥和代理配置 |
| `POST /api/sandbox/cube/test` | 验证填写的连接，临时实例测试后释放，不隐式保存 |
| `DELETE /api/sandbox/cube` | 释放当前账号实例并移除连接 |

新表由 Alembic `0003_cube_connection` 管理；API 和 Worker 启动自动升级。后端需安装更新后的 requirements。API 和 Worker 必须连接同一个业务库、共享本地文件区。
验证结果和运行时间由 `0004_cube_runtime_status` 管理。
终端记录由 `0005_terminal` 管理，持续 PTY 的 PID 由 `0006_cube_pty` 管理。反向代理需转发 WebSocket 的 Upgrade/Connection 头，示例 nginx 已补齐；浏览器请求经过 Next 同源代理，不直接获得 Cube API Key。

Cube 后端已部署时不需要在 Botly 主机安装 KVM 或 Cube 服务。使用自签名 TLS 时，按 Cube 部署文档安装信任证书；requests 可配置 `REQUESTS_CA_BUNDLE`，httpx 可配置 `SSL_CERT_FILE`，不要关闭证书验证。

未保存个人 Cube 连接时使用部署级回退：默认 `BOTLY_SANDBOX_PROVIDER=none` 不启动沙箱；显式设为 `docker` 才使用本机 Docker 测试后端。其他服务端 SDK 仍可通过 `external` + `BOTLY_SANDBOX_ADAPTER=包.模块:类名` 接入。
